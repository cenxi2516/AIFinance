# Stock-Pick.skill

LLM 驱动的多策略 A 股选股工具 — 主题锚定 → 多策略漏斗 → 批判审核 → 反馈闭环。

## 核心承诺

给定选股需求，返回一个经过多策略过滤和风险审核的股票清单：

`市场主线识别 → 候选池结构化 → 11策略逐一匹配 → 资金流增强 → 三维度风险否决 → 分层输出（通过/拒绝+原因）→ 反馈持久化`

## 三技能协作关系

```
a-stock-data（数据获取层）
    │
    ├── serenity-skill（基本面层）→ "该不该关注"
    └── stock-pick（选股层）     → "具体选哪只"
```

| 维度 | serenity-skill | stock-pick |
|------|---------------|------------|
| 职责 | 产业链瓶颈基本面分析 | 多策略选股筛选 |
| 输入 | 产业链知识 + 财报/公告 | 全市场/板块行情数据 |
| 输出 | 稀缺层判断 + 标的优先级 | 通过/拒绝分层清单 |
| 时间维度 | 中长期（季度-年度） | 短期-中期（天-周） |

**推荐组合使用**：serenity-skill 确定"该不该关注"→ stock-pick 筛选"具体选哪只"。

## 请求路由

| 用户意图 | 触发模式 | 说明 |
|---------|---------|------|
| "帮我选股""筛选""最近机会""荐股" | **完整流水线** | 7 阶段全跑 |
| "只看XX板块的标的" | **主题限定模式** | 跳过 Phase 2 主题锚定，直接候选池 |
| "审核这几只""这只怎么样" | **纯 critic 模式** | 跳过筛选，直接对给定标的做三维度审核 |
| "更新反馈库""反馈库加一条" | **反馈维护模式** | 仅操作 `src/_feedback/` 文件 |
| "查看我的反馈库" | **反馈查看** | 读取并总结反馈库中的经验教训 |

## 完整流水线

```
Phase 1: 反馈加载       → 读取历史经验约束
Phase 2: 主题锚定       → 识别当前市场主线
Phase 3: 候选池构建     → 结构化全市场/板块候选
Phase 4: 多策略过滤     → 11 种技术形态策略逐一匹配
Phase 5: 辅助信号增强   → 资金流跟踪 + 可选逆向信号
Phase 6: 批判审核       → 三维度风险打分否决
Phase 7: 反馈更新       → 被拒标的关键特征持久化
```

### Phase 1: 反馈加载

**目的**：从历史坏案例中提取经验约束，注入后续筛选上下文。

**操作**：
1. 读取 `src/_feedback/` 目录下所有 JSON 文件
2. 提取每条记录的：失败特征、策略标签、拒绝原因、时间戳
3. 归约为"经验约束清单"，按频率排序（出现 ≥3 次的高频失败模式重点标注）

**输出示例**：
```
经验约束清单（来自历史反馈）:
1. [高频] 光模块板块高位利好冲高回落 → 警惕借利好出货形态（出现5次）
2. [高频] 半导体设备突破后缩量回踩失败 → 回踩需放量确认（出现3次）
3. ...
→ 以上约束将在 critic 阶段作为重点检查项
```

**文件不存在时**：跳过此阶段，使用默认 critic 标准。

### Phase 2: 主题锚定

**目的**：识别当前市场主线，缩小选股范围到最有赚钱效应的方向。

**数据来源**：
- 同花顺热点板块（a-stock-data §3.1 `tonghuashun_hot_sectors()`）→ 当日强势板块 + 题材归因
- 东财行业板块排名（a-stock-data §3.8 `eastmoney_industry_rank()`）→ 涨跌幅 + 上涨下跌家数
- 北向资金流向（a-stock-data §3.2 `tonghuashun_north_flow()`）→ 外资偏好方向

**LLM 判断逻辑**：
1. 从热点板块中识别反复出现的概念/行业关键词
2. 判断是否形成"主线"（连续 ≥3 天出现在热点前10、有龙头打出高度、资金持续流入）
3. 输出 ≤3 个主题标签（如"AI光模块""半导体设备""低空经济"）

**输出**：
```json
{
  "themes": ["AI光模块", "半导体设备"],
  "confidence": "高",
  "rationale": "AI光模块连续5日热点前3，龙头中际旭创创新高；半导体设备北向连续流入",
  "user_override": false
}
```

**用户可覆盖**：如果用户指定了板块/主题，跳过此阶段。

### Phase 3: 候选池构建

**目的**：在主题范围内构建结构化的候选股票池。

**步骤**：

1. **拉取数据**（依赖 a-stock-data）：
   - 概念板块归属：`eastmoney_concept_blocks()` — 获取主题相关全部个股
   - 基础信息：mootdx finance 快照 / 东财个股信息 — PE/PB/市值/换手率
   - K线数据：mootdx `get_kline()` 或腾讯 K线 API — 近期 OHLCV
   - 资金流：东财 `eastmoney_fund_flow_minute()` — 资金流向概要
   - 热度信号：同花顺热点匹配度

2. **结构化**（按 `candidate_keys` schema，详见 `assets/candidate-keys.json`）：
   ```
   基础信息: code, name, sector, concept
   主题属性: theme, theme_type, theme_context{score, trend, risk_penalty}
   资金情绪: money_flow_summary, popularity_summary
   交易规则: allow_long, selection_source
   ```

3. **固定条件初筛**（硬规则，直接过滤）：
   - 剔除 ST/*ST 股票
   - 剔除近 5 日日均成交额 < 5000 万（流动性门槛）
   - 剔除近 20 日跌停 ≥2 次（异常波动）
   - 剔除上市不足 60 个交易日（次新股不稳定）

**输出**：结构化候选池（通常 200-600 只，取决于板块大小）。

### Phase 4: 多策略过滤

**目的**：用 11 种 LLM 驱动的技术形态策略逐一匹配候选池，每个策略产出匹配子集。

**执行方式**：
- LLM 读取 Phase 3 产出的结构化数据（K 线、均线、RSI、换手率、成交量、波动率等）
- 逐个策略遍历候选池，每个标的标注匹配的策略标签（可匹配多个策略）
- 最终汇总去重，输出"综合候选名单"（每个标的带策略标签和匹配理由）

**11 策略简表**（完整定义见 `references/strategies.md`）：

| # | 策略 | 一句话逻辑 | 关键数据 |
|---|------|----------|---------|
| 1 | 突破确认回踩 | 突破关键位后回踩确认支撑 | 前高/MA60、回踩深度、量能 |
| 2 | 大成交额超低强弱 | 放量恐慌后 RSI 低位超跌反弹 | 成交额排名、RSI(14) |
| 3 | 低波动超低强弱 | 缩量横盘后方向选择 | ATR、振幅、相对强度 |
| 4 | 低波动超低RSI | 低波动 + RSI<30 超卖反弹 | ATR、RSI、MA60偏离 |
| 5 | 低涨幅入场 | 短期滞涨的补涨标的 | 5/10/20日涨幅、相对板块涨幅 |
| 6 | 强势回调入场 | 前期强势股回调支撑位 | 前期涨幅排名、回调幅度、缩量 |
| 7 | 高强度低换手回调 | 趋势强+换手低=主力锁仓 | ADX、换手率、筹码集中度 |
| 8 | 低涨幅低换手 | 横盘蓄势主力吸筹 | 涨幅分位、换手率分位、横盘天数 |
| 9 | 均线上方低RSI | 上升趋势中的RSI回调买点 | MA20/MA60、RSI、回调距离 |
| 10 | 强庄回调入场 | 强庄股回调至成本区 | 连续放量、大单净流入、成本估算 |
| 11 | 低涨幅筛选 | 宽基兜底，仅看短期涨幅 | 5/10日涨幅排名 |

**策略开关**：用户可通过 `--enable-strategies` / `--disable-strategies` 控制策略开关，默认全部启用。

**输出**：按策略标签分组的候选列表 + 综合候选名单（去重）。

### Phase 5: 辅助信号增强

**目的**：对 Phase 4 的综合候选名单追加资金面和情绪面的辅助判断。

**子模块**：

1. **资金流跟踪（money_follow）**：
   - 对 Phase 4 候选标的，拉取东财个股资金流 120 日数据（a-stock-data §4.5）
   - LLM 判断：主力资金是否持续流入（5/10/20日主力净流入趋势）
   - 标注"资金面支持"/"资金面中性"/"资金面背离"

2. **逆向情绪信号（contrarian，默认关闭）**：
   - 拉取东财个股新闻（a-stock-data §5.1）+ 同花顺热点匹配度
   - LLM 判断：是否出现"过度悲观"的散户情绪（可作为逆向指标）
   - 用户通过 `--contrarian` 启用

**输出**：带资金/情绪标注的增强候选名单。

### Phase 6: 批判审核（critic）

**目的**：对每个候选标的从三个维度做风险打分，排除伪机会。

**三维度打分**（完整评分标准见 `references/critic-rubric.md`）：

| 维度 | 权重 | 核心检查项 |
|------|------|----------|
| 技术面风险 | 40% | 上影线、避雷针、乖离率、放量下跌、跌破支撑、缩量反弹 |
| 主力行为 | 35% | 借利好出货、高位减仓、融资异常、大宗折价、机构净卖出 |
| 主题周期 | 25% | 热度退潮、龙头破位、反弹尾声、政策利空、缺乏催化 |

**决策规则**：

| 总分 | 判定 | 动作 |
|------|------|------|
| 0-4 | 低风险 | ✅ 通过 |
| 5-7 | 中风险 | ⚠️ 通过，标注风险提示 |
| 8-10 | 高风险 | ❌ 拒绝，记录原因 |
| >10 | 极高风险 | 🚫 强制拒绝 |

**输出格式**：
```
✅ 通过审核 (kept=N):
  - 600xxx 贵州茅台 | 策略: 均线上方低RSI, 低涨幅入场 | critic=3.5 | 资金面支持
  - ...

❌ 被拒标的 (rejected=M):
  - 300308 中际旭创 | critic=7.0 | 反弹极弱+长上影，主力借利好出货
  - 688525 佰维存储 | critic=8.0 | 38%超长上影避雷针，主力高位减仓
  - ...

📋 风险提示清单:
  - [标的A] 注意：融资余额偏高，需跟踪
  - [标的B] 注意：板块龙头已走弱，谨慎追高
```

### Phase 7: 反馈更新

**目的**：将本轮被拒标的关键特征写入反馈文件，形成持续学习的闭环。

**操作**：
1. 提取被拒标的的关键特征（板块、策略标签、拒绝原因、技术形态关键词）
2. 写入 `src/_feedback/` 目录，文件名 `feedback-YYYY-MM-DD.json`
3. 合并历史反馈：如果同类拒绝模式已存在，更新频率计数；否则新增记录

**反馈记录格式**（详见 `assets/feedback-template.json`）：
```json
{
  "date": "2026-06-15",
  "pattern": "高位避雷针+利好出货",
  "code": "688525",
  "name": "佰维存储",
  "sector": "半导体存储",
  "matched_strategies": ["强势回调入场"],
  "reject_reason": "38%超长上影避雷针，主力高位减仓",
  "technical_signals": ["长上影>5%", "放量冲高回落", "高位"],
  "critic_score": 8.0,
  "frequency": 3
}
```

**用户确认**：默认自动写入，用户可通过 `--no-feedback` 跳过更新。

## 反馈闭环

### 反馈文件目录

```
src/_feedback/
├── feedback-2026-06-13.json
├── feedback-2026-06-14.json
├── feedback-2026-06-15.json
└── _summary.json              # 汇总：高频失败模式 + 统计
```

### 反馈使用流程

```
每次选股 → Phase 1 加载历史反馈 → 注入经验约束
    → 筛选完成 → Phase 7 写入新反馈 → _summary.json 自动更新
```

### 经验约束归约（LLM 定期执行）

当 `src/_feedback/` 中记录超过 20 条时，LLM 自动归约：
- 合并同类失败模式（板块+技术形态相似 → 同一模式）
- 提取频率 ≥3 的高频模式 → 升级为"重点关注约束"
- 超过 90 天的低频率记录 → 自动归档，不参与归约

## 风险边界

- **研究支持，不做交易执行**：筛选结果是基于公开技术面数据的分析参考，最终买卖决策、时机、仓位由用户自行判断
- **策略依赖技术形态**：所有策略基于技术面数据（K 线、均线、成交量等），不考虑内幕信息或非公开数据
- **LLM 推理存在主观性**：策略匹配结果可能因 LLM 推理差异而不同，建议多次运行交叉验证
- **历史模式不代表未来**：反馈库中的经验约束是对历史失败的归纳，不代表未来相同模式一定失败
- **不覆盖极端事件**：突发政策、黑天鹅事件、公司重大利空可能导致技术形态完全失效
